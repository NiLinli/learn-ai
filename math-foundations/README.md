## 这份笔记解决什么问题

RAG、embedding、向量库的文档里总出现「余弦相似度」，但大学毕业多年，数学基本忘了。这里不推导公式，只回答三件事：

1. 它到底在算什么？
2. 为什么分数越高就越像？
3. 看到 0.65、0.19 这种数字，怎么判断好坏？

## 一句话结论

**余弦相似度 = 两支箭头夹角的「方向一致分」**，范围 −1 到 1；越接近 1 越像，接近 0 表示基本无关，负数表示方向相反。

## 先补四个符号

| 符号 | 读法 | 白话意思 |
| --- | --- | --- |
| `a` | 向量 a | 一串数字，也可以想成一支箭头 |
| `\|a\|` | a 的长度 | 这支箭头有多长 |
| `a · b` | a 点乘 b | 对应位置的数字相乘，再全部加起来 |
| `cos θ` | 余弦 | 夹角 θ 的「方向一致分」，一个 −1 到 1 的数 |

下面用到的运算只有加、减、乘、除和开平方，不需要三角函数表。

## 1. 向量：一串数字，也是一支箭头

二维向量 `(3, 4)` 表示：往右走 3，往上走 4。它是一支箭头，终点在坐标 `(3, 4)`。

```text
y
4 |        ● (3, 4)
3 |      /
2 |    /
1 |  /
0 +------------ x
  0 1 2 3
```

embedding 模型输出的向量是 1024 维，也就是 1024 个数字。人脑画不出 1024 维的箭头，但「方向」「长度」「夹角」这些概念仍然成立，计算方式也完全一样。

## 2. 长度：箭头有多长

二维向量 `(x, y)` 的长度：

```text
|a| = √(x² + y²)
```

`(3, 4)` 的长度是 `√(3² + 4²) = √25 = 5`。这就是勾股定理，不需要记别的。

## 3. 点积：对应位置相乘，再相加

`a = (3, 4)`，`b = (4, 3)`：

```text
a · b = 3×4 + 4×3 = 12 + 12 = 24
```

点积有一个几何性质：

```text
a · b = |a| × |b| × cos θ
```

把它移项，就得到余弦相似度的公式：

```text
cos θ = (a · b) / (|a| × |b|)
```

不需要证明这个性质，把它当成一个「换算器」：**点积除以两个长度，就得到夹角的余弦。**

## 4. 余弦：夹角越小，分数越高

| 夹角 | 余弦 | 白话含义 |
| --- | --- | --- |
| 0° | 1 | 方向完全一致 |
| 45° | 0.707 | 比较像 |
| 90° | 0 | 基本无关（垂直） |
| 180° | −1 | 方向完全相反 |

```text
b ↗        c ↑        d ←
  ↘        |          |
   a →     a →        a →
夹角小     垂直       反向
cos≈1     cos=0      cos=−1
```

实际文本 embedding 的分数通常落在 0 到 1 之间，但出现负数也不奇怪。

## 5. 手算两个例子

### 例子 A：比较像

```text
a = (3, 4)
b = (4, 3)

a · b = 3×4 + 4×3 = 24
|a| = 5
|b| = 5
cos = 24 / (5×5) = 0.96
```

0.96 很接近 1，说明两支箭头方向几乎一致。

### 例子 B：垂直，基本无关

```text
a = (3, 4)
c = (−4, 3)

a · c = 3×(−4) + 4×3 = −12 + 12 = 0
|a| = 5
|c| = 5
cos = 0 / 25 = 0
```

点积为 0，余弦就是 0。几何上两支箭头垂直。

### 例子 C：同方向，但长度不同

```text
a = (3, 4)
d = (6, 8)   ← 正好是 a 的两倍长

a · d = 3×6 + 4×8 = 18 + 32 = 50
|a| = 5
|d| = 10
cos = 50 / (5×10) = 1
```

方向完全一样，所以余弦是 1。**长度不影响余弦**，这正是它适合比较文本语义的原因。

## 6. 为什么要「归一化」

如果只看点积，长向量会占便宜：

```text
a · d = 50，而 a · b = 24
```

但 `d` 只是 `a` 的放大版，并不比 `b` 更像 `a`。除以两个长度之后，长度的影响被消掉，只剩方向。

工程上常做的「归一化」就是：

```text
把每个向量除以自己的长度，让它变成单位向量（长度为 1）
```

归一化之后：

```text
a · b = cos θ
```

因为两个长度都变成了 1。demo 里的 `vector_rag.py` 就是这么做的：建库时归一化，查询时也归一化，然后直接算点积。

## 7. 1024 维怎么算

公式完全一样，只是项数变多：

```text
a · b = a₁b₁ + a₂b₂ + ... + a₁₀₂₄b₁₀₂₄
```

也就是 1024 次乘法、1023 次加法，再开两个平方根。计算机做这些是微秒级的事。

人不需要在脑子里画 1024 维的图，只需要知道：

- 每个维度是一个「特征方向」
- 点积在累加「两个向量在同一方向上的共同强度」
- 除以长度后，得到方向的一致程度

## 8. 和 RAG 的关系

embedding 模型把一段文本变成向量。语义相近的文本，向量方向也相近，所以可以用余弦比较。

demo 里的真实分数：

| 文本 | 与问题的余弦 |
| --- | --- |
| 量化把权重用更少的 bit 表示……不改变参数量 | **0.6556** |
| 微调……改变权重的数值，不改变参数量 | 0.6351 |
| 公司年假需要提前三天申请 | **0.1942** |

问题：`量化会改变参数量吗？文件体积怎么估算？`

0.65 和 0.19 的差距，就是「相关」和「无关」的差距。但**阈值不是通用的**：换一个 embedding 模型，分数分布会变，必须用评测集重新校准。demo 里的 0.45 只对 `qwen3-embedding:0.6b` 校准过。

还有一条硬规则：建库和查询必须用同一个 embedding 模型，否则两边的向量不在一个空间，余弦没有意义。

## 9. 常见坑

| 坑 | 说明 |
| --- | --- |
| 把余弦相似度和余弦距离搞反 | 相似度越大越像；距离 = 1 − 相似度，越小越像 |
| 向量没归一化就直接点积 | 点积会被长度带偏；要么归一化，要么确认模型/库的度量 |
| 用不同模型编码 query 和文档 | 向量空间不一致，分数不可比 |
| 拿一个固定阈值套所有模型 | 不同模型的分数分布不同，阈值要单独校准 |
| 零向量 | 长度为 0，除法没有意义；实际系统要过滤 |
| 以为分数必须为正 | 余弦范围是 −1 到 1，文本任务里通常为正，但不保证 |

## 10. 三句话总结

1. 向量是一支箭头；余弦相似度看的是两支箭头的夹角。
2. 点积除以两个长度，就得到 −1 到 1 的方向分。
3. 分数越高越像；阈值要按模型校准，不能照搬。
